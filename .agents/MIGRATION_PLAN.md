# 新员工培训系统迁移计划

所有阶段遵循：不复制参考 HTML，不绕开现有 Vue/Element Plus/Router/Pinia/Axios 体系；用户手动执行构建与验收。

## 阶段一：项目结构和调用链确认（本次完成）

- 目标：确认源码、Docker、Nginx、容器、菜单、路由、练习接口和参考原型。
- 涉及文件：本目录文档、`Dockerfile`、Nginx 模板、路由、菜单、练习页及服务文件（均只读）。
- 可复用代码：现有 `ProTable`、组织筛选、SOP QA 服务、布局菜单。
- 新增代码：无。
- 风险：后端练习/考试模型和正式分类源未确认。
- 验收条件：本文档集和调用链表完整，且不改正式页面。

## 阶段二：新增考试管理菜单和路由占位

- 目标：在培训中心安全加入“考试管理”入口和空占位路由。
- 涉及文件：`src/stores/modules/auth.ts`、`src/router/index.js`、`src/languages/modules/zh.ts`、`en.ts`、`th.ts`，以及最小占位页面文件。
- 可复用代码：菜单元数据、`SubMenu.vue`、布局与路由守卫。
- 新增代码：一个懒加载页面；无专用 API、无数据库变更。
- 风险：无考试权限码；若产品要求后端动态菜单，应先停下确认。
- 验收条件：登录后培训中心出现入口，路由可达，既有菜单与深链接不回归。

## 阶段三：改造练习管理静态布局

- 目标：以参考练习页的筛选、表格、生成/编辑和题目管理目标改造 Vue 页面外观与交互骨架。
- 涉及文件：优先 `src/pages/LicenseAdmin.vue`；仅在实际需要时增加同目录局部组件与样式。
- 可复用代码：`ProTable`、`ReviewDialog.vue`、现有组织选择和 Element Plus 表单/抽屉。
- 新增代码：一级/二级分类 UI、名称筛选、参考所需操作入口；不引入新依赖。
- 风险：参考的“练习”不等同当前 SOP 记录；不得伪造后端字段。
- 验收条件：用户手动确认布局、筛选区、列表、弹窗和空/加载态与现有管理端风格一致。

## 阶段四：练习管理接入现有接口

- 目标：把经确认可映射的列表、导入/生成 QA、任务状态、题目复核、编辑、删除接入改造后的页面。
- 涉及文件：`LicenseAdmin.vue`、其局部组件、`services/sop.api.js`；如资料选取可行，再评估 `mobile.service.js`。
- 可复用代码：全部已存在的 SOP 与组织服务封装。
- 新增代码：仅字段适配与错误提示；服务接口不足时不猜测端点。
- 风险：`saveQaList` 当前封装形参与调用不一致；资料选择和分类字段契约未知。
- 验收条件：用户手动验证每个已确认接口、401、空数据、生成中、失败与批量删除行为。

## 阶段五：实现考试管理静态页面

- 目标：基于参考考试页实现 Vue/Element Plus 的列表、状态/分类筛选、创建抽屉、步骤预览和发布 UI，不接假接口。
- 涉及文件：预计 `src/pages/examManagement/index.vue`，按复杂度添加该目录局部组件。
- 可复用代码：布局、菜单、ProTable、表单、抽屉、确认提示；练习列表选择能力在字段契约确认后复用。
- 新增代码：考试 UI 状态与表单校验。
- 风险：普通分类/混合考试规则、题目来源和发布状态尚无正式数据模型。
- 验收条件：用户手动验证创建、编辑、预览、混合考试最少跨两类练习限制及草稿/发布/结束展示。

## 阶段六：考试管理接口设计和接入

- 目标：在后端提供并确认契约后接入考试列表、详情、保存、删除、发布、题目来源和记录 API。
- 涉及文件：预计 `src/services/exam.service.js`、考试页面及局部组件；后端/数据库文件待后端仓库确认。
- 可复用代码：Axios 拦截器模式、SOP QA 题目数据线索、用户考试会话服务（仅在后端确认复用时）。
- 新增代码：最小 API 封装和状态映射。
- 风险：不能因 `chatapi/v1/exams/*` 存在而假定它支持管理端试卷/发布。
- 验收条件：用户按真实接口手动验收 CRUD、发布、题量分值、状态转换及错误返回。

## 阶段七：权限、异常状态和数据兼容

- 目标：补齐后端确认的权限码、隐藏规则、无权提示、加载/空/失败状态和旧数据兼容。
- 涉及文件：按实际权限来源决定；可能包括 auth store、路由守卫、菜单适配、服务和页面。
- 可复用代码：token 拦截器、现有 `isHide` 菜单过滤、Element Plus 提示。
- 新增代码：只补真实权限/字段差异，不创建抽象权限层。
- 风险：当前没有后端动态菜单或权限码证据。
- 验收条件：不同角色、旧练习数据、接口异常和深链接均由用户手动验证。

## 阶段八：用户手动验收

- 目标：按 `ACCEPTANCE_CHECKLIST.md` 完成业务验收。
- 涉及文件：无代码必改；发现缺陷按最小范围修复。
- 可复用代码：验收清单。
- 新增代码：仅验收发现的必要修复。
- 风险：未联调后端接口前不能宣称完成。
- 验收条件：用户确认练习、考试、菜单、权限、分类、异常提示与视觉一致性。
